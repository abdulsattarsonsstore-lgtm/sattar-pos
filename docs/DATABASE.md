# Abdul Sattar Sons POS - Database Design

## Project

Abdul Sattar Sons POS

---

# Database

Supabase PostgreSQL

---

# Overview

The current POS database supports:

- Product management
- Inventory
- Customer management
- Sales
- Billing
- Sale items
- Invoice generation
- Stock deduction
- Customer activity status

Important business logic for completing a sale is implemented in PostgreSQL through the `complete_sale()` function.

---

# Current Tables

The current verified database contains four primary application tables:

1. `products`
2. `customers`
3. `sales`
4. `sale_items`

---

# 1. products

## Purpose

Stores every product available in the shop.

## Columns

| Column | Type | Nullable | Default |
|---|---|---:|---|
| id | bigint | No | Generated identity |
| product_name | text | No | — |
| category | text | No | — |
| brand | text | Yes | — |
| barcode | text | Yes | — |
| purchase_price | numeric | No | — |
| selling_price | numeric | No | — |
| stock | integer | Yes | 0 |
| unit | text | Yes | — |
| low_stock | integer | Yes | 5 |
| description | text | Yes | — |
| created_at | timestamp with time zone | Yes | now() |

## Identity

`id` is:

`GENERATED ALWAYS AS IDENTITY`

Sequence:

`products_id_seq`

## Constraints

- Primary key: `products_pkey`
- Unique barcode: `products_barcode_key`
- Purchase price must be non-negative.
- Selling price must be non-negative.
- Stock must be non-negative.
- Low-stock value must be non-negative.

---

# 2. customers

## Purpose

Stores customer information used by the POS.

## Columns

| Column | Type | Nullable | Default |
|---|---|---:|---|
| id | bigint | No | Generated identity |
| name | text | No | — |
| phone | text | No | — |
| address | text | Yes | — |
| created_at | timestamp with time zone | No | now() |
| updated_at | timestamp with time zone | No | now() |
| is_active | boolean | No | true |

## Identity

`id` is:

`GENERATED BY DEFAULT AS IDENTITY`

Sequence:

`customers_id_seq`

## Constraints

- Primary key: `customers_pkey`
- Customer name cannot be blank.
- Customer phone cannot be blank.

---

# 3. sales

## Purpose

Stores every completed sale and its payment information.

## Columns

| Column | Type | Nullable | Default |
|---|---|---:|---|
| id | bigint | No | Generated identity |
| invoice_number | text | No | — |
| subtotal | numeric | No | 0 |
| discount | numeric | No | 0 |
| total | numeric | No | 0 |
| payment_method | text | No | 'Cash' |
| amount_paid | numeric | No | 0 |
| notes | text | Yes | — |
| created_at | timestamp with time zone | No | now() |
| amount_received | numeric | Yes | — |
| change_due | numeric | No | 0 |
| customer_id | bigint | Yes | — |

## Identity

`id` is:

`GENERATED BY DEFAULT AS IDENTITY`

Sequence:

`sales_id_seq`

## Constraints

- Primary key: `sales_pkey`
- Invoice number is unique.
- Amount paid must be non-negative.
- Discount must be non-negative.
- Discount cannot be greater than subtotal.
- Subtotal must be non-negative.
- Total must be non-negative.

## Customer Relationship

`sales.customer_id`

references:

`customers.id`

Delete behavior:

`ON DELETE RESTRICT`

This prevents deletion of a customer that is referenced by a sale.

# 4. sale_items

## Purpose

Stores the individual products included in a completed sale.

The table also stores historical product information so that previous sales retain the product name, unit, selling price and purchase cost used at the time of sale.

## Columns

| Column | Type | Nullable | Default |
|---|---|---:|---|
| id | bigint | No | Generated identity |
| sale_id | bigint | No | — |
| product_id | bigint | Yes | — |
| product_name | text | No | — |
| quantity | integer | No | — |
| unit | text | Yes | — |
| unit_price | numeric | No | — |
| unit_cost | numeric | No | — |
| line_total | numeric | No | — |
| created_at | timestamp with time zone | No | now() |

## Identity

`id` is:

`GENERATED BY DEFAULT AS IDENTITY`

Sequence:

`sale_items_id_seq`

## Constraints

- Primary key: `sale_items_pkey`
- Quantity must be greater than zero.
- Unit price must be non-negative.
- Unit cost must be non-negative.
- Line total must be non-negative.

## Sale Relationship

`sale_items.sale_id`

references:

`sales.id`

Delete behavior:

`ON DELETE CASCADE`

Deleting a sale therefore deletes its associated sale items.

## Product Relationship

`sale_items.product_id`

references:

`products.id`

Delete behavior:

`ON DELETE SET NULL`

This allows historical sale records to remain even if the associated product is later deleted.
